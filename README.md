# ZENTRA — демо-проект биржи цифровых активов

Полноценный (в рамках демо) проект: реальная регистрация и вход, база
данных на диске, сессии на cookie, генерация демо-адресов для депозита
при регистрации. Фронтенд — без градиентов, плоские элементы.

## ⚠ Важно понимать перед использованием

- Адреса для депозита (BTC/ETH/USDT), которые генерируются при регистрации,
  **случайны и не подключены к реальному блокчейну**. Это витрина интерфейса,
  а не настоящие кошельки. Отправка на них реальных средств приведёт к их
  потере — предупреждение об этом показано прямо в личном кабинете.
- Это не готовая к продакшену финансовая инфраструктура. Реальный приём
  депозитов, кастодиальное хранение и биржевой матчинг требуют лицензии,
  партнёра по хранению (Fireblocks / BitGo / Copper и т.п.) и security-аудита.
- Пароли хранятся хешированными (Node.js `crypto.scrypt`), но база — простой
  JSON-файл на диске. Для реального продакшена замените `server/db.js` на
  PostgreSQL/MySQL/SQLite.

## Стек

- **Backend:** Node.js + Express (без сборки, без TypeScript — просто и прозрачно)
- **База данных:** JSON-файл (`data/db.json`), создаётся автоматически при первом запуске
- **Сессии:** подписанные cookie-токены (HMAC-SHA256), без сторонних сервисов
- **Frontend:** обычные HTML/CSS/JS, без фреймворков и сборщиков

## Запуск локально

```bash
npm install
npm start
```

Откройте http://localhost:3000

Для разработки с автоперезапуском:

```bash
npm run dev
```

## API

| Метод | Путь                 | Описание                                  |
|-------|----------------------|--------------------------------------------|
| POST  | `/api/auth/signup`   | Регистрация: `{ username, password }`      |
| POST  | `/api/auth/login`    | Вход: `{ username, password }`             |
| POST  | `/api/auth/logout`   | Выход, очищает cookie сессии               |
| GET   | `/api/me`            | Данные текущего пользователя (нужна cookie)|
| GET   | `/api/health`        | Проверка, что сервер жив                   |

## Переменные окружения

Создайте `.env` (не коммитится) или задайте переменные на хостинге:

```
PORT=3000
SESSION_SECRET=замените-на-длинную-случайную-строку
NODE_ENV=production
```

Без `SESSION_SECRET` используется значение по умолчанию из кода — это
нормально для локальной разработки, но обязательно замените его перед
реальным деплоем.

## Деплой

GitHub сам по себе только хранит код — чтобы сайт с сервером работал в
интернете (не просто как статичная страница), нужен хостинг с поддержкой
Node.js. Подойдут, например, Render, Railway или Fly.io — на любом из них:

1. Подключаете репозиторий с GitHub
2. Указываете команду запуска `npm start`
3. Задаёте переменную окружения `SESSION_SECRET`

GitHub Pages **не подойдёт** — он отдаёт только статичные файлы и не
запускает Node.js-сервер, а значит регистрация и вход работать не будут.
